# Design diversity contract

Design diversity means different visual systems that still solve the same user task. It does
not mean producing many expensive images or changing only color.

## Design DNA axes

Describe each proposed direction using these axes before rendering:

- `composition`: split workspace, preview-first canvas, dense control room, modular board,
  editorial flow, or another task-appropriate structure
- `density`: calm, balanced, or compact
- `typography_voice`: neutral technical, editorial, geometric, humanist, or another justified
  voice
- `surface_language`: flat, outlined, layered, tactile, glass only when justified, or another
  coherent treatment
- `color_strategy`: monochrome with accent, restrained brand color, semantic color, tonal color,
  or another accessible strategy
- `imagery`: none, product screenshot, diagram, photography, illustration, or data visualization
- `motion_character`: none, functional, expressive, or cinematic; name its purpose

## Evidence mix

Use no more than one source for each role unless the user asks for more:

1. a structural reference for information hierarchy and layout
2. a visual reference for typography, surface, and color
3. an interaction reference for motion or state behavior

Record the exact section and properties used. Never copy branding, copy text, proprietary
assets, or an entire site identity.

## Diversity gate

- Two directions must differ on at least three relevant Design DNA axes.
- The primary task, real data, viewport, and required actions stay fixed for comparison.
- Every direction must be implementable with the approved stack or declare the missing tool.
- Do not render a direction that is only a theme swap.
- Do not use a named style without a visible reference or a concrete written fingerprint.
- A user-approved existing direction remains a valid baseline.

## Cost control

Start with text fingerprints and small structure sketches. Render one direction after selection.
If the user cannot choose, render at most two materially different directions in one comparison
artifact. A rejected direction is preserved with its rejection reason and is not regenerated
unchanged.

## What a Skill cannot guarantee

A Skill can guide decisions, run checks, and preserve a repeatable workflow. It cannot by itself
guarantee taste, originality, valid licenses, usable product behavior, accurate real data,
production performance, or user satisfaction. Those require visible references, working code,
browser evidence, and user approval.
