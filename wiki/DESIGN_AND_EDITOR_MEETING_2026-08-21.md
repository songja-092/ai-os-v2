# 디자인 탐색·인터뷰·편집기 회의 — 2026-08-21

## 회의 상태

- 인터뷰 우선 제작 시작: 사용자 승인
- Design DNA 최종 흐름: 회의 중
- 편집기 최종 채택: 미결정
- PM1·PM2 잠금: 유지
- 현재 활성 PM: PM3

## 1. 인터뷰 우선 제작 시작 결정

V2는 디자인 회사처럼 제작에 필요한 범위를 먼저 확인하고, 사용자는 고객처럼 결과와
범위를 확인합니다.

```text
사용자 요청
→ 작업 크기 분류
→ 전체·짧은·생략 인터뷰
→ 제작 범위 확인서
→ 사용자 확인
→ 해당 제작 흐름 시작
```

규칙:

- 새 프로젝트·새 결과물: 전체 인터뷰
- 큰 기능 변경: 기존 답을 재사용한 짧은 인터뷰
- 승인 범위 안의 명확한 작은 수정: 인터뷰 생략
- 모호함·충돌: 질문 하나
- 사용자 확인 전 제작 시작 금지
- 출력은 Versioned Intent Packet과 제작 범위 확인서
- 원본 `Interview Me` Skill을 모든 요청에 자동 실행하거나 전역 설치하지 않음
- PM5가 최종 Core 계약을 소유하고 PM1~PM4는 수동 Gate로 선사용

## 2. 디자인 탐색·채택 흐름 회의안

현재 합의된 방향:

```text
사용자 요청과 제작 범위 확인
→ 기존 성공 Recipe 우선 검색
→ 부족하면 수집기가 후보 탐색
→ 접근·라이선스·구현 불가능 후보 제거
→ 디자인 총괄이 서로 다른 방향 3개 제시
→ 사용자 화면 선택
→ 선택한 후보·부분에서만 정식 Design DNA 추출
→ 사용할 부분과 제외할 부분 정리
→ Visual Target 하나 제작
→ 실제 문구·데이터·모바일 확인
→ 사용자 디자인 승인
→ Design Recipe 승격
→ 구현·마감·기능·접근성·회귀검증
→ 사용자 최종 승인
→ 성공 Recipe·DNA·거절 이유 저장
```

선택 전에는 상세 DNA를 만들지 않고 후보를 구별하기 위한 간단한 분류만 사용합니다.
정식 DNA는 사용자 선택 뒤 구조·정보 밀도·Typography·색상·공간·Component·Motion을
선택된 부분에서만 추출합니다.

현재 증거:

- 공급원 10개 시각 Trial과 사용자 판정: 존재
- 채택 공급원 5개→Section→Draft Recipe Trace: PASS
- 자동 후보 수집: 미구현
- 선택 뒤 정식 7축 DNA 추출: 미구현
- 최종 Visual Target→실제 제품→Fidelity→Restore E2E: BLOCKED
- 첫 Blocker: `antigravity_execution`

## 3. 오늘 확인한 V2 전체 MCP 확장 후보

사용자가 이 다섯 후보를 찾은 이유는 PM3 편집기만 교체하기 위해서가 아닙니다.
현재 편집기가 카드 3개 중심의 작은 Pilot이라 자유도가 낮다고 느꼈고, V2 전체의
디자인 탐색·구현·편집·검증·3D 제작을 보완하면서 Codex·Antigravity가 직접 연결해
사용할 수 있는 MCP 후보를 조사하다 나온 목록입니다.

따라서 다섯 개를 같은 편집기끼리 경쟁시키지 않습니다. 각 후보가 V2 전체 흐름의
어느 병목을 해결하는지 따로 판정합니다.

### 실제 격리 Pilot

- `Puck 0.22.4 + React Grid Layout 2.2.4`
- 카드 3개 구조·배치·크기·속성, 이미지 Slot, 단색·투톤 Palette, Auto Draft, Undo 검증
- `Motion 12.23.12`가 Pilot에 설치됨
- Core Registry 승격·실제 고객 제품 전체 적용·사용자 PM3 PASS는 아직 아님

### 신규 미설치 MCP 후보

- `Penpot MCP`: 작은 PM3 편집기의 자유도를 보완할 정밀 시각 편집 후보. 공식 MCP는
  존재하지만 V2 Recipe 연결·비용·보안·사용성 격리 검증 전이며 Puck 대체로 확정하지 않음
- `Raven MCP`: V2 전체 UX·글자·간격·접근성 검사를 보완할 후보. UI UX Pro와 중복 확인 전
- `Blender MCP`: 브랜드형 고객 웹·3D 결과물 제작을 확장할 후보. 운영 Dashboard 기본 기능 아님

### 구현·검증 MCP 후보

- `shadcn MCP`: 새 Module·Component·Block을 실제 코드로 가져오는 구현 재료. PM2 잠금을
  다시 여는 기능이 아니라 향후 모든 제작 프로젝트에서 사용할 구현 공급원 후보
- `Storybook MCP`: 재사용 Module의 정상·로딩·빈 화면·오류 상태를 AI가 조회하고 검증할 후보

다섯 MCP의 V2 역할 후보:

| MCP 후보 | 해결하려는 V2 병목 | 현재 상태 |
| --- | --- | --- |
| shadcn MCP | 검증된 구현 부품 부족 | 미연결 후보 |
| Storybook MCP | Module 상태·재사용·회귀 증거 부족 | 미연결 후보 |
| Raven MCP | 디자인·UX 마감 검사의 빈틈 | 미연결·중복 확인 전 |
| Penpot MCP | 현재 부분 편집기의 낮은 자유도 | 미설치 비교 후보 |
| Blender MCP | 3D·브랜드형 고객 결과물 제작 한계 | 미래 프로젝트 후보 |

## 4. 다음 회의 판정 방식

후보마다 실제 기능, 설치·운영 부담, 기존 V2 기능과 중복, 비공개 프로젝트 보호,
Design Recipe 연결, 제거 가능성, 사용자 체감 가치를 조사한 뒤 사용자가 다음 중 하나를
판정합니다.

- 채택
- 보류
- 폐기

기술 연결과 격리 검증은 Codex가 수행하고 최종 채택은 사용자가 결정합니다.

다섯 후보와 추가 MCP의 공식 자료·로컬 호환성 조사 결과는
`wiki/MCP_CANDIDATE_REVIEW_2026-08-21.md`를 사용합니다. 조사만 완료했으며 설치·설정·
Core 연결은 수행하지 않았습니다.
