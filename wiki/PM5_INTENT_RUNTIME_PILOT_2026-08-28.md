# PM5 사용자 의도·범위 확인 Runtime Pilot — 2026-08-28

## 현재 판정

- `전자명함을 만들 거야` 원문을 그대로 보존합니다.
- 여러 화면과 개인정보를 포함하므로 `Spec Full`로 처리합니다.
- PM4에서 잠근 2번 디자인 방향, 전체 8개 화면, 사진 원본 보존 계약을 입력으로 사용합니다.
- 이름·사진·전화·이메일·연결 주소 등 필수 자료가 비어 있으면 `이대로 시작`을 차단합니다.
- 사용자가 승인하면 별도 구현용 전달서만 만들며 제품·UI·배포는 변경하지 않습니다.
- 승인 뒤 답변 수정·범위 재열기·이전 버전 복원이 발생하면 기존 전달서를 즉시 `stale_due_to_intent_change`로 표시합니다.
- 별도 입력 양식 대신 PM4에서 승인한 전체 8개 전자명함 화면과 소유자 편집 영역을 한 화면에 연결했습니다.
- PM4 승인 화면 8개 뒤에 PM5 파생 상태인 `9. 최종 완료` 화면을 추가했습니다.
- 단순 기능 카드로 보이던 최초 구현을 폐기하고 PM4 승인 이미지 자산, 흰색·검정·라임 색상, 인물 중심 구성, 4열 비교 구조로 다시 맞췄습니다.
- 최초 Design QA는 잘린 인물·QR·배경 중복·의미가 불명확한 테마 편집·Visual Target 없는 완료 화면을 놓치고 잘못 PASS했습니다. 사용자 검토로 이 판정을 취소하고 `blocked`로 되돌린 뒤 수정했습니다.
- 9번은 PM4 Visual Target을 입력으로 ImageGen Visual Target을 별도 생성했고, 생성 Adapter·입출력 Hash·Prompt 계약을 `screen-9-completion-visual-target.json`에 Core Artifact로 기록했습니다.
- 1번은 승인된 메인 화면 전체, 3번은 완전한 QR Crop, 6·7번은 배경 없는 인물 Crop을 사용하며 8번은 대표 색상과 행동 순서의 적용 대상을 화면에 설명합니다.
- `테스트 정보로 전체 화면 시험하기`는 실제 개인정보 없이 필수 입력과 화면 동시 반영을 확인하며, 사용자 승인 전에는 구현 전달을 허용하지 않습니다.

## 확인된 증거

- 격리 Runtime Fixture: 정상 입력, 누락 차단, 승인, 수정 후 승인 무효화, 이전 버전 복원, 재시작 복원 PASS
- Browser: 전체 8개 화면 표시, 테스트 정보 동시 반영, 입력 저장·복원, 승인 버튼 차단, Console 앱 오류 없음
- PM4 잠금 파일 Hash 유지 PASS

## 아직 사용자 판단이 필요한 것

- 실제 개인정보를 입력할지, 테스트용 가짜 정보로 먼저 검증할지
- 실제 입력 완료 후 제작 범위 승인

## 증거 경계

이 결과는 전자명함 한 프로젝트의 PM5 Runtime Pilot입니다. 임의 프로젝트 범용 PM5, 실제 제품 구현, 배포, 사용자 최종 승인을 증명하지 않습니다.

현재 전자명함 화면은 Core가 상태·입력·승인 차단·복원·PM4 승인 자산 제공을 소유하고 Browser Runtime에서 재현합니다. Product Design 절차는 시각 구현과 QA Adapter로 사용했으며, 임의 주제를 같은 방식으로 자동 제작하는 범용 Core Adapter는 아직 없습니다. 따라서 이번 결과를 모든 V2 제작의 자동화 증거로 확대하지 않습니다.
