# Goal

AI OS V2는 코딩을 전혀 모르는 사용자가 자연어로 원하는 소프트웨어를 설명하고, AI의 조사·기획·설계 결과를 눈으로 확인하고 선택하면서 실제로 작동하는 소프트웨어까지 완성할 수 있도록 돕는 개발 환경을 목표로 합니다.

사용자는 기술적인 코딩 작업보다 원하는 결과의 설명, 선택, 수정 요청과 최종 승인에 집중합니다. AI는 검증된 Skill, GitHub 오픈소스, 기존 자산과 성공 사례를 먼저 조사하고 재사용하며, 필요한 경우에만 최소한으로 직접 구현합니다.

아이디어·계획·구현·검증 상태를 명확히 구분하여 아직 구현되지 않은 것을 구현된 것처럼 표현하지 않습니다. 개발 과정과 확정된 결정은 Wiki와 GitHub에 지속적으로 보존하여 ChatGPT, Codex, Antigravity 등 작업 AI가 같은 프로젝트 기억을 공유할 수 있도록 합니다.

V2는 기존 `ai_os`의 코드를 이식하거나 완성하는 프로젝트가 아닙니다. 기존 `ai_os`는 사용자 요구, UX 아이디어와 실패 원인을 확인하는 참고 자료로만 사용합니다. V2의 실제 기능은 검증된 외부 부품을 새 저장소에서 조립하고, 대체 수단이 없는 연결부만 최소 구현합니다.

V2의 성공은 기능 수가 아니라 다음 한 흐름이 실제 증거와 함께 반복 가능한지로 판단합니다.

`자연어 요청 → 조사 → 명세와 설계 → 사용자 승인 → 구현 → 실제 실행 검증 → 사용자 확인 → Git 저장 → 복구`

## 완성 목표와 발전 가능한 Core 방향

V2의 완성 목표는 모든 업종과 기능을 미리 내장하는 것이 아니라, 현재 없는 능력도 안전하게 조사·시험·검증해 새로운 제작 능력으로 편입할 수 있는 개인용 소프트웨어 제작·유지보수 OS입니다.

보험, 영상 마케팅, 육아처럼 처음 접하는 분야도 전문가인 것처럼 즉시 구현하지 않습니다. 먼저 현재 Core·Skill·프로젝트의 능력과 부족한 역할을 확인하고, 공식 문서·검증된 Skill·유지관리되는 오픈소스·API·기존 자산을 순서대로 조사합니다. 필요한 경우에만 격리된 작은 파일럿이나 최소 연결 코드를 만들며, 사용자 승인과 실제 환경 검증을 통과한 결과만 재사용 후보로 보존합니다.

확장 흐름은 다음을 고정합니다.

`새 요청 → 현재 능력 확인 → 부족한 역할 식별 → Skill·공식 OSS·API 조사 → 격리 파일럿 → 사용자 승인 → 구현·독립 검증 → Commit·복구점 → 재사용 후보 승격`

도구가 발견되거나 설치됐다는 사실을 구현·검증 완료로 표현하지 않습니다. 후보는 실제 프로젝트 실행, 실패 처리, 사용자 확인, Result Commit과 Rollback/Restore를 통과한 뒤에만 재사용 가능한 Recipe로 승격합니다. 로그인·개인정보·결제·배포·규제 분야처럼 위험도가 높은 확장은 별도 승인과 전문 검증을 요구합니다.

따라서 목표가 흔들릴 때는 기능 수가 아니라 다음 질문을 기준으로 판단합니다.

> V2가 현재 없는 기능도 기존 Core를 다시 설계하지 않고, 검증된 외부 능력과 최소 연결부를 안전하게 추가하고 검증·복구·재사용할 수 있는가?
